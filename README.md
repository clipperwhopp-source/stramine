# STRAMINE official website

A bilingual, static studio website for WallPair and Bi Dürüm Usta!. The site is generated by `site.py` from `data/apps.json`, then served from `docs/` on GitHub Pages. It needs Python 3 and has no third-party runtime dependencies, backend, analytics, cookies or JavaScript bundle.

## Build and check

```sh
python3 site.py
python3 scripts/check_site.py
```

After deployment, `python3 scripts/check_live.py` checks every canonical public page and the previously inventoried app URLs, then writes `reports/live-http-check.json`.

Open locally with a symlink so `/stramine/` resolves:

```sh
mkdir -p work/preview-root
ln -s "$(pwd)/docs" work/preview-root/stramine
python3 -m http.server 8765 --directory work/preview-root
```

The local URL is `http://127.0.0.1:8765/stramine/`. The production URL is `https://clipperwhopp-source.github.io/stramine/`.

## Add a future app

1. Add a new object to `data/apps.json`. Set `published` to `false` while preparing it. Required fields are `slug`, `name`, `short_name`, `type`, `category`, `store_seller`, `icon`, `screenshots`, `app_store`, `google_play`, `privacy_original`, `support_original`, `policy_date`, `available`, `seo` and bilingual `copy`. A `genre` sentence is optional. Keep `google_play` as `null` until a public listing works. Use `SoftwareApplication` or `VideoGame` for `type`.
2. Put approved app icon and actual approved screenshots in `docs/assets/`; use descriptive filenames. `screenshots` may be one list shared across languages or an object with `en` and `tr` lists. The first screenshot is the hero image.
3. Verify store links, published privacy/support links and content. Set `published` to `true` only when the product is authorized for public display. The generator ignores unpublished entries.
4. Run both commands above, inspect the new English and Turkish product, privacy and support pages in a browser, and check mobile width.
5. Commit the source and regenerated `docs/`, then push `main`. GitHub Pages publishes from `main` `/docs`; check the live pages after deployment.

The shared page templates, app directory, privacy/support hubs and sitemap automatically include every published entry. An app-specific account deletion route is currently written for WallPair because its approved instructions already exist; new account deletion routes must be added only when verified.

## Deployment and path strategy

GitHub Pages is configured to publish `main` `/docs` from the public `clipperwhopp-source/stramine` repository. The generator defaults to `SITE_URL=https://clipperwhopp-source.github.io/stramine` and `BASE_PATH=/stramine`. Changing host or repository path requires setting `STRAMINE_SITE_URL` and `STRAMINE_BASE_PATH` during generation, reviewing canonical URLs, sitemap, redirects and asset paths, then deploying the regenerated `docs/` tree. Do not set a new host until it is actually controlled and tested.

Existing WallPair deep links and all old policy/support sites remain independent. See `STRAMINE_EXISTING_WEB_ASSETS_AUDIT.md` before changing any established URL.
